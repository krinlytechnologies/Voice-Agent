# Mona AI Voice Agent — Architecture

> Reverse-engineered from the source and last verified on 2026-10-26 (type-check clean;
> `vitest run`: 17 files, 100 tests passing). This describes what the code does today, not what
> marketing copy or the roadmap claims. Known problems are in [issues.md](./issues.md).

## 1. What this project is

A marketing site plus an admin dashboard for "Mona", an AI voice-calling product, built with
Lovable (lovable.dev) and TanStack Start (React 19, file-based routing, SSR via Nitro).

- The public landing page embeds a working ElevenLabs conversational widget (a separate demo agent).
- The dashboard is **partly live**: sign-in, campaigns, lead import, the credits widget, the calling
  activity chart and the "Book a demo" form use Supabase. The Voice Leads, Prompts, Outbound Calls,
  Missed Callbacks and Call Outcome Rules pages, and the lower half of the Overview, still run on
  in-memory sample data (see §6).
- Real calling is done by a **separate Python service, the voice engine** (the `agent` repository:
  Exotel telephony, ElevenLabs Scribe speech recognition, OpenRouter LLM, Bakbak text-to-speech).
  Only part of the contract between the two exists (see §8). No UI action can start a call yet.

## 4. Auth model

- **Dashboard sign-in:** real Supabase email/password auth (`src/lib/auth.ts`). `WorkspaceShell` redirects to `/login`
  when there is no session. Whether public sign-up is enabled is a Supabase dashboard setting that is **not visible in
  this repository** (`supabase/config.toml` only holds the project id), so check it there.
- **Server functions:** campaigns, leads, prompts and workspace functions all run behind `requireSupabaseAuth`, which
  validates the Supabase JWT. Row-level security policies (migrations) scope data to the user's client.
- **Voice-engine webhook:** authenticated by an HMAC-SHA256 of the raw body (`x-voice-engine-signature`), using a shared
  secret, and then uses the service-role client because the engine has no Supabase session.
- `src/integrations/supabase/cron-auth.ts` (secret rotation support) has no caller yet.

## 5. Database schema (Supabase/Postgres)

Tenancy and billing (`0000_super_admin_foundation.sql`): `app_role` enum, `user_roles`, `profiles`, `clients` (with
`credit_balance`), `client_members`, `credit_transactions` (a trigger adjusts the balance and refuses to go negative),
and `calls` (minimal call log).

`0001_demo_requests.sql`: `demo_requests`. Anyone may insert; only super admins may read.

`0002_campaigns_voice_engine.sql`:

- `campaigns`, `leads` (unique per campaign + phone), `prompts` and immutable `prompt_versions`, all RLS-scoped to the client.
- `voice_engine_jobs`: one dispatch of a campaign to the engine, with a unique `idempotency_key` and a unique index that
  allows **at most one active job per campaign**.
- `voice_engine_webhook_events`: every webhook delivery, unique on `event_id`, so retries and replays are no-ops.
- Extra columns on `calls`: `campaign_id`, `lead_id`, `job_id`, `transcript_url`, `engine_call_id`.

## 6. Domain modules (`src/lib/*.ts`)

Pure, browser-safe modules with colocated tests: `campaigns.ts` (types, CSV parsing), `campaign-setup.ts` (wizard
validation), `voice-leads.ts` (sample distribution), `call-records.ts` (generated sample calls), `prompts.ts` (persona
model), `call-outcome-rules.ts`, `branding.ts`, `error-capture.ts` / `error-page.ts` / `lovable-error-reporting.ts`.

Server functions (Supabase-backed, covered by tests): `campaigns.functions.ts` (list, create, status, details, dispatch),
`leads.functions.ts`, `workspace.functions.ts` (credits, overview), `prompts.functions.ts` (list, save version),
`campaigns.adapter.ts` (maps rows to the UI shapes).

**Languages.** `promptLanguages` in `prompts.ts` is limited to **English, Tamil, Hindi, Telugu**, the languages the voice
engine can speak. The server schema in `prompts.functions.ts` enforces the same list. Keep it in sync with the engine's
`Language` type (`app/models.py`).

## 7. UI layer (`src/components/dashboard/*`, `src/components/ui/*`)

Pages share `WorkspaceShell` (sidebar, sign-out, credits widget). `VoiceAgent.tsx` is the landing-page ElevenLabs widget.
`DemoDialog.tsx` inserts into `demo_requests`. The campaign wizard's voice picker offers fixed labels (for example
"Voice 8 · Reflective Women · Female") that are **not** the engine's voices.

## 8. Voice-engine integration

Code: `src/lib/voice-engine/` (`client.ts`, `types.ts`, `webhook.ts`), `campaigns.functions.ts#dispatchCampaign`,
`src/routes/api/webhooks/voice-engine.ts`.

| Part of the contract | Mona sends / expects | Python engine (`agent/app/dispatch.py`) |
|---|---|---|
| Auth | `Authorization: Bearer $VOICE_ENGINE_API_KEY` | Same header; the key is the engine's `APP_SECRET_KEY` |
| Health | `GET /health` → `{status: "ok", active_calls}` | Implemented (public, answers 500 if its database is down) |
| Dispatch | `POST /campaigns/dispatch` (leads, calling window, retry policy and a `persona` copy) | Implemented. Answers `accepted` + `engineJobId`, or `rejected` + `reason` (outbound disabled, persona language not speakable, campaign already running, no webhook secret). The body's `idempotencyKey` makes retries safe. |
| Job status / cancel | `GET /jobs/{id}`, `POST /jobs/{id}/cancel` | Implemented. Cancel stops new calls, is idempotent, and lets a call in progress finish. |
| Events | Signed webhooks (`X-Voice-Engine-Signature`, HMAC-SHA256 hex of the raw body) | `call.completed`, `call.failed`, `job.completed`, `job.cancelled`. Delivered in order per job, retried with backoff until a 2xx. `call.started` and `job.failed` are accepted by Mona but never sent. |
| Single call | not used | `POST /calls` `{agent_id, to, contact_name?}` places one outbound call |

### How a campaign runs

1. **Start** (Campaign page): `startCampaignDispatch` checks the campaign is not Completed and the workspace has credits,
   sends the Queued leads to the engine, and on `accepted` stores the job and sets the campaign **Active**. Numbers shorter
   than 10 digits cannot be dialled: they are marked Exhausted / "Invalid number" and not sent.
2. **What the agent says** is the persona saved on the Prompts page. Start reads the campaign's persona (workspace +
   persona key) and sends a copy: name, language, instructions, greeting, knowledge and revision number (also stored on the
   job as `persona_version`). The engine keeps that copy on the job and builds the call's prompt from it, so a call always
   says the revision that was current when its campaign was started; saving a new revision affects the next start only.
   Start is refused if the persona was deleted, is switched off, or is in a language the engine cannot speak.
3. **Calling**: the engine's dispatcher loop dials one lead at a time (up to `MAX_CONCURRENT_CALLS`) inside the campaign's
   calling window (India time). The voice is the engine's (`BAKBAK_VOICES` for the persona's language, or overrides on the
   engine agent row kept per workspace + persona key); the campaign's voice label is informational.
4. **Each attempt** produces a `call.completed` or `call.failed` event. Mona records a `calls` row, links it to the lead
   (only if the lead belongs to the job's own campaign), adds 1 to `attempts`, and sets the lead's queue state:
   Done, Retry scheduled (with the follow-up time), Exhausted (tries used up), or back to Queued (cancelled mid-run).
   A reached call is retried when its outcome is `no_conversation`; unanswered, busy and failed calls are always retried
   until the campaign's maximum tries.
5. **Finish**: when every lead is done or exhausted the engine sends `job.completed` with the connected minutes. Mona debits
   `ceil(minutes × VOICE_ENGINE_CREDITS_PER_MINUTE)` credits once, and sets the campaign **Completed**.
6. **Pause / Complete** (Campaign page): Mona first asks the engine to cancel the job. If the engine cannot be reached the
   status is not changed, so a campaign never shows Paused while calls could still go out. The engine finishes the call in
   progress, then sends `job.cancelled` (credits for the minutes used are debited).

### Inbound routing

Mona tables `inbound_numbers` (the draft: globally unique E.164 phone, workspace, persona key, conversation type, on/off)
and `inbound_publications` (every publish attempt with the exact snapshot sent, status `pending`/`synced`/`failed`, and a
partial unique index allowing one `pending` per number). What callers hear is the newest `synced` publication, never the
draft or the saved prompt.

| Contract | Detail |
|---|---|
| `PUT /inbound/routes` (Bearer) | `{phone, clientId, version, active, persona}`; `persona` is the same `PersonaIn` that dispatch sends. `200 {status: "applied" \| "unchanged"}`. `409 {detail: {code: "stale_version", currentVersion}}` when the version is lower than the engine's; `409 version_conflict` for the same version with different content; `409 number_taken` when the number belongs to another `clientId`; `422 persona_unspeakable`. |
| `GET /inbound/routes/{phone}` (Bearer) | the stored route (`version`, `active`, `personaKey`, `personaVersion`, `workflow`, `clientId`) or 404 |
| Stream start | the engine reads `start.to` from Exotel's `start` event and normalises it to digits with the country code first (`+91…`, `91…`, `0…` and bare ten-digit forms are the same number) |

A call whose `CallSid` has no outbound row is inbound: a published, active route answers with its persona (the same
overlay campaign calls use); an unrouted number is refused, or answered by the engine-wide default agent (no
`client_id`) while `INBOUND_LEGACY_DEFAULT_ENABLED=true`. A workspace's agent is never used as the default. Versions
only increase: Mona sends `max(its publications, the engine's last reported version) + 1`, and a rollback re-sends an
earlier snapshot as a new version. `INBOUND_RESERVED_CALLS` slots are never given to outbound or campaign calls.

### Inbound call reports

A finished inbound call is queued by the engine **in the same database transaction that saves the call** (a failure to
queue is logged and never undoes the saved call), then delivered from the dispatcher's own delivery loop, so a slow
dashboard cannot hold up dialling or any live call. One report per call (unique on `call_id`).

| Part | Contract |
|---|---|
| Destination | `DASHBOARD_WEBHOOK_URL` (engine setting), because an inbound call has no dispatch job to carry a URL. Reports are queued only when this and `DASHBOARD_WEBHOOK_SECRET` are both set. |
| Signature | `X-Voice-Engine-Signature` = hex HMAC-SHA256 of the raw request body, the same scheme as campaign events. Mona verifies it against the exact bytes received before parsing anything. |
| Event | `eventType: "call.completed"` (the existing name) with `data.direction: "inbound"` and **no `engineJobId`**. Top level: `schemaVersion` (1), `eventId` (uuid, unique), `eventType`, `occurredAt` (ISO 8601 with offset). |
| `data` | `direction`, `engineCallId`, `dialledNumber` (digits, country code first), `callerNumber`, `durationSeconds`, `status`, `outcome` (the engine's original word), `summary`, `collectedFields`, `transcriptRef`. |
| `transcriptRef` | The engine call id as an opaque key, or `null` when there was no conversation. It is **not** a link. Mona reads the transcript server-side with the engine's authenticated `GET /calls/{id}` after checking the call belongs to the caller's workspace and that the engine's record is the same call. |
| Answers | `2xx` handled (including a duplicate). `400/403/404/409` can never be accepted: not retried. `401` bad signature. `408/425/429` and `5xx` or a network failure: retried with growing delays, at most `WEBHOOK_MAX_ATTEMPTS` times, then kept with its last error. |

Mona's handling (`src/lib/voice-engine/inbound-events.ts`): validate the body against a strict schema (types, ranges, sizes);
find the workspace from `inbound_numbers` by the dialled number, **ignoring any workspace named in the message**; refuse a
number that is unknown (404), never published, switched off both as a draft and as published, or whose published route
belongs to a different workspace than its mapping (403); record the `eventId` and write the call in one transaction, so a
repeat is acknowledged without a second row and a failure leaves nothing behind; keep the newest report when two arrive for
the same call out of order; refuse to overwrite a call recorded for another workspace or as a campaign call (409). No
credits are touched.

`calls` now carries: `direction`, `caller_number`, `dialled_number` (our number for inbound, the contact's for outbound),
`status`, `outcome` (Mona's label), `outcome_raw` (the engine's word), `summary`, `collected_fields`, `transcript_ref`,
`inbound_number_id`, `reported_at`. `src/lib/outcomes.ts` holds the mapping; unknown words become *Inconclusive*.

The engine fills the prompt placeholders `[[KNOWLEDGE]]`, `[[CALLER_CONTEXT]]` and `[[CURRENT_DATETIME]]` (India time)
that Mona's persona instructions use. `[[CALLER_CONTEXT]]` carries the call direction and, for outbound calls, the
`contact_name` (never a phone number).

Still not connected: the persona's recognition context, WhatsApp message and call-behaviour settings, the campaign's voice
choice and Call Outcome Rules are not sent, inbound calls do not use Mona personas, the engine's outcome words
(for example `appointment_requested`) are stored as-is rather than mapped to Mona's outcome list, transcripts have no link,
and the credit cap and mid-run credit exhaustion are not enforced. See the open items in [issues.md](./issues.md).

## 9. Testing

Vitest with jsdom. Pure `src/lib` modules are well covered, as are the auth middleware, the campaign, lead, prompt and
workspace server functions, and the voice-engine client and webhook. There are no component tests for dashboard pages, no
login-page test, and no test for the ElevenLabs widget.

## 10. Environment configuration

`.env` (local, not committed): `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_PROJECT_ID` and `VITE_` copies for
the browser bundle.

Needed on the server for the features above, none of which are set in the local `.env`: `SUPABASE_SERVICE_ROLE_KEY`
(webhook handler), `VOICE_ENGINE_BASE_URL`, `VOICE_ENGINE_API_KEY` (= the engine's `APP_SECRET_KEY`),
`VOICE_ENGINE_WEBHOOK_SECRET`, `APP_BASE_URL` (builds the webhook URL), optionally `VOICE_ENGINE_CREDITS_PER_MINUTE`
(default 1), and `LOVABLE_CRON_SECRET` / `LOVABLE_CRON_SECRET_PREVIOUS` for the unused cron authenticator.
